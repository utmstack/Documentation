SOC-AI is the AI assistant built into UTMStack v12. You ask it questions in plain language about your alerts, logs and detections, and it can also act for you: update alerts, open incidents, build dashboards and response flows, and more. It can also look at every new alert on its own and write an assessment on it.

## Before you start

- An AI provider must be set up in **Configure > Settings > SOC-AI**. A new installation uses the ThreatWinds provider without any key once the instance is registered. See **AI Providers**.
- Until a provider is set up, the assistant's buttons are hidden, and AI options such as **Using AI** for new flows are locked.
- In UTMStack v12.0.2 the assistant is shown only to users who can open the SOC-AI settings, that is the **Administrator** role. Analysts and Viewers do not see it.
- Each question and each alert analysis counts against the daily AI allowance of your tenant, if one is set. See **AI Usage and Limits**.

## Where you find it

| Place | Label | What it does |
|---|---|---|
| Top bar | **Ask** | Opens the assistant panel. |
| **Overview** | "What would you like to know from your security data?" with suggestions **Threat hunt**, **Observable triage**, **Write a rule**, **Current system status** | Starts a conversation from the home page. |
| Alert details | **Ask** | Opens the assistant with this alert shared. **Stop sharing with the assistant** removes it. |
| Incident details | **Ask** | Opens the assistant with this incident shared. |
| **Live Operations** | **Ask SOC-AI** | Opens the assistant from the live view. Unlike the other buttons, it is shown to everyone, but it works only when a provider is set up and, in UTMStack v12.0.2, only for the Administrator role. |
| Alert details | **Generate AI summary** | Asks SOC-AI to investigate the alert and add an assessment (see below). |
| **SOAR > Flows** | **Using AI** (new flow), **Edit with AI** (flow editor) | Drafts or changes a response flow. See **Building a Flow**. |
| **Dashboards** | **Using AI** > **Create with AI** (new dashboard), **Edit with AI** | Drafts or changes a dashboard. |

## The assistant panel

The panel is titled **SOC Assistant**. When it is empty it reads "Ask anything about your alerts, detections or the console — I can investigate and act on the SIEM." and suggests a first question, "how many open alerts, grouped by adversary?".

| Control | What it does |
|---|---|
| **Send** | Sends your question. |
| **Collapse** / **Expand** | Shrinks or enlarges the panel. |
| **Clear conversation** | Starts over. |
| **Copy** | Copies an answer. |
| **Close** | Closes the panel. |

In a long conversation you may see "Compacting context…" while the assistant shortens what it remembers.

Conversations are kept in your browser only. UTMStack does not store them on the server, so they are not shared with colleagues and are gone when you clear them or reload the page.

## How it works

The assistant works in a loop: it plans, calls one of UTMStack's tools, looks at the result, and repeats until it can answer. The number of rounds is capped by **Max tool iterations** in the SOC-AI settings (default 12). The tools are the same ones UTMStack offers to outside AI clients; see **MCP Server**.

Read-only tools are always available to the assistant, for example log and alert search, SQL queries over logs and alerts, and counts. In a conversation it can also use these groups of tools:

| Group | What the assistant can do |
|---|---|
| Alerts | Change status, tags and notes; manage tag rules. |
| Incidents | Create and manage incidents. |
| Dashboards | Create and manage dashboards and widgets. |
| Compliance | Manage frameworks and controls, and generate reports. |
| Correlation | Manage correlation rules, pipelines (event-processing filters) and regex patterns. |
| Data sources | Manage data sources. |
| SOAR | Create and manage response flows. |

<Warning>

The assistant changes things for real. If you ask it to close alerts, change a rule or create a flow, it does so. Check what it reports it did, and review flows and rules it creates before you switch them on.

</Warning>

## Automatic alert triage

When **Auto-analyze alerts** is on in the SOC-AI settings, SOC-AI investigates every new alert on its own:

1. It replaces some personal data before the alert goes to the AI: the user names and email addresses of the target and the adversary, and of the target in the alert's last event, become placeholders (see **What data goes to the AI provider** below).
2. It judges the alert together with the score UTMStack computes for it. Only when that leaves the picture unclear does it investigate further with tools.
3. It writes its assessment as a note on the alert, starting with `[AI SOC Agent]`.

The alert then carries the **AI assessed** badge, and its details show a **SOC AI assessment** section with a risk level and a score out of 100.

During triage, SOC-AI may change only alerts. With **Allow managing incidents** on, it may also create or update incidents when it decides an alert deserves one. It never changes dashboards, compliance, rules, data sources or flows during triage.

On a new installation using the ThreatWinds default, both switches are off.

<Note>

In testing of UTMStack v12.0.1, automatic triage also analysed repeat alerts (echoes), and on a busy server its queue could fall behind. Watch your AI usage after you turn it on.

</Note>

## Analyse one alert on demand

In the alert details, click **Generate AI summary** ("SOC-AI investigates this alert and adds an assessment."). The request is queued and the assessment is written on the alert when it is ready, usually after about a minute. If it takes longer, you see "The AI summary is taking longer than expected. It will show up on the alert when it is ready."

## What data goes to the AI provider

The AI provider you choose in **Configure > Settings > SOC-AI** receives the data below. Requests go from your UTMStack server straight to the provider's address (listed in **AI Providers**); with the default ThreatWinds provider they go to ThreatWinds.

| Feature | What is sent to the provider |
|---|---|
| Chat: the assistant panel, **Ask** buttons, and the AI builders for dashboards and flows | Your message; up to the last 10 messages of the conversation; the alert or incident you shared with the assistant; UTMStack's instructions and the list of tools the assistant may use; and the result of every tool the assistant calls while it answers, such as log lines, alerts, incidents and search counts. |
| Automatic triage and **Generate AI summary** | The alert, up to 100,000 characters. Automatic triage sends it with its last event (the alert's other events are left out); **Generate AI summary** sends only the alert's own fields, such as name, description, severity, adversary and target, without its events or notes. In both cases also the alert's score, which UTMStack computes itself, and, when the first pass asks for a deeper look, the results of the tools it calls. |

**What is replaced before sending.** For automatic triage and **Generate AI summary** only, UTMStack replaces these values with placeholders before the alert leaves the server:

- the user name and email address of the alert's target and adversary;
- the user name and email address of the target in the last event (automatic triage only, because only it sends the last event);
- email addresses inside the text values of the last event's `log` fields (automatic triage only).

The model is told which fields were replaced, so it does not draw conclusions from the placeholders.

**What is not replaced.** IP addresses, host names, the origin user of the last event, the original log text (`raw`), the contents of chat messages, and everything that tools return during a chat or a deeper triage are sent as they are.

**What is stored where.**

- Chat conversations are kept only in your browser.
- Assessments are stored in UTMStack as a note on the alert, starting with `[AI SOC Agent]`. Everyone who can read the alert can read the note.
- What the provider keeps, and for how long, depends on the provider's own terms.

If your data must not leave your network, run a model on your own infrastructure (Ollama, or any OpenAI-compatible server) and choose it as the provider. See **AI Providers**.

## Permissions

| Permission | Description | Built-in roles |
|---|---|---|
| `socai.read` | "Use the SOC AI assistant" | Administrator, Analyst, Viewer |
| `socai.write` | "Configure the SOC AI provider" | Administrator |

Because the assistant's buttons depend on the settings check, in UTMStack v12.0.2 only users with `socai.write` see them.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| No **Ask** button and no **Generate AI summary** | No provider is set up, or your role cannot open the SOC-AI settings (in UTMStack v12.0.2 only the Administrator role sees the assistant). | Set up a provider in **Configure > Settings > SOC-AI** (see **AI Providers**). |
| "this tenant has used the AI requests its plan allows for today" | The tenant's daily AI allowance is used up. | Wait until midnight UTC, or ask the instance operator to raise the tenant's cap. See **AI Usage and Limits**. |
| "rate limit reached — upgrade to Enterprise for higher usage limits" | The AI provider refused the request because too many were sent. With ThreatWinds, the limit comes from your subscription; with other providers, from your account with them. | Wait a few minutes and ask again. With your own provider, check your plan's limits. |
| "SOC AI agent unreachable" or "SOC AI agent timed out" | The SOC-AI service on the UTMStack server is not running or did not answer in time. | Check the server's services (see **Health Checks and Troubleshooting**) and try again. |
| "An error has occurred while processing your request." | The AI provider returned an error, for example because the model or key changed. | Check the provider, model and key in **Configure > Settings > SOC-AI**. Saving a changed provider, model, address or key tests the connection again. |
| The assistant stops before it finishes the task | It reached **Max tool iterations** (default 12). | Ask a narrower question, or raise **Max tool iterations** in the SOC-AI settings. |
| Answers are cut off | They reached **Max tokens** (default 4096). | Raise **Max tokens** in the SOC-AI settings. |
| "Compacting context…" in a long conversation | The conversation is too long for the model, so the assistant shortens what it remembers. | Normal. For a new topic, click **Clear conversation**. |
| New alerts get no SOC AI assessment | **Auto-analyze alerts** is off; the tenant's allowance for the day is used up (automatic triage then skips alerts); or more than 1,000 alerts are waiting, in which case new ones are skipped. | Check the switch and **AI allowance today** in the SOC-AI settings. On a busy server, analyse important alerts with **Generate AI summary**. |
| **Generate AI summary** shows "The AI summary is taking longer than expected…" | The provider is slow, or many alerts are waiting for analysis. | The assessment is added to the alert when it is ready. |

## Not the same as AI Analyst

**Threat Intelligence > AI Analyst** is a threat intelligence feature, separate from the SOC-AI assistant. It is described with the threat intelligence pages.
