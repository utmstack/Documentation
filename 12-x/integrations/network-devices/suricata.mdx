UTMStack v12 collects Suricata IDS/IPS events through the **UTMStack Forwarder**, which the web interface calls the **Collector**. Suricata writes its EVE JSON events to the local syslog service, and rsyslog forwards them to the Collector. Nothing else is installed on the Suricata host.

## Connection details

| Setting | Value |
|---|---|
| Card on the Integrations page | **Suricata** (category IDS / IPS) |
| Data type | `suricata` |
| Default ports on the Collector | 7019/UDP; 7019/TCP (also used for TLS) |
| Included in UTMStack | A parsing filter and 35 detection rules |

## Before you begin

- A Collector must be installed and online. If you do not have one, see **UTMStack Forwarder**. One Collector can serve all your integrations.
- The Suricata host must reach the Collector host on the port you choose. Open it on the Collector host and on any firewall in between.
- You need the `integrations.write` permission to enable the integration from the web interface.
- The Suricata host needs rsyslog installed and running.

## Step 1: Enable the integration on a Collector

<Steps>
  <Step title="Open the integration">
    In UTMStack, go to **Configure > Integrations** and open the **Suricata** card.
  </Step>
  <Step title="Choose the Collector, protocol and port">
    Under **Enable this integration remotely**, select the **Collector**, the **Protocol** (**UDP**, **TCP** or **TLS**) and the **Port**. The port fills in with the default for the protocol.
  </Step>
  <Step title="Enable it">
    Click **Enable integration**. The panel then shows, for example, `Currently: enabled · udp · port 7019`.
  </Step>
</Steps>

To do the same on the Collector host instead, run:

```bash
sudo /opt/utmstack-forwarder/utmstack_forwarder enable-integration suricata 7019 udp
```

To use TLS, load a certificate on the Collector first. See **UTMStack Forwarder**.

## Step 2: Send Suricata EVE events to syslog

Suricata is collected as JSON (EVE). On the Suricata host, edit `suricata.yaml` and configure the `eve-log` output to write to syslog:

```yaml
outputs:
  - eve-log:
      enabled: yes
      filetype: syslog
      facility: local5
      types:
        - alert
        - dns
        - http
        - tls
        - flow
```

Then restart Suricata:

```bash
sudo systemctl restart suricata
```

## Step 3: Forward syslog to the Collector

Point the `local5` facility, where Suricata now writes, at the Collector. Add this line to `/etc/rsyslog.d/60-utmstack-suricata.conf` on the Suricata host. Replace `<collector-ip>` with the address of the Collector host.

```text
local5.*  @<collector-ip>:7019
```

`@` sends over UDP. Use `@@` instead to send over TCP, and enable the integration with TCP in step 1. Then restart rsyslog:

```bash
sudo systemctl restart rsyslog
```

<Note>

The setup guide in UTMStack fills in your UTMStack server's address in this step. Keep it only if the Collector runs on the UTMStack server; otherwise use the address of the Collector host.

</Note>

## Step 4: Check that logs arrive

- In the **Suricata** drawer, click **View logs**. Log Explorer opens with the `suricata` data type for the last 24 hours.
- Within about 10 minutes, the Suricata host appears on the **Data Sources** page under **Direct**.
- **Rules** and **Filters** in the same drawer open the detection rules and the parsing filter for this data type.

## Stop collecting

In the **Suricata** card, select the same Collector and click **Disable integration**, or run on the Collector host:

```bash
sudo /opt/utmstack-forwarder/utmstack_forwarder disable-integration suricata udp
```
