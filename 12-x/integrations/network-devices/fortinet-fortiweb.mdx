UTMStack v12 collects Fortinet FortiWeb web application firewall logs through the **UTMStack Forwarder**, which the web interface calls the **Collector**. You enable the FortiWeb integration on a Collector, then create a syslog policy on the FortiWeb that points at that Collector. Nothing is installed on the FortiWeb.

## Connection details

| Setting | Value |
|---|---|
| Card on the Integrations page | **Fortiweb** (category Firewall) |
| Data type | `firewall-fortiweb` |
| Default ports on the Collector | 7018/UDP; 7018/TCP (also used for TLS) |
| Included in UTMStack | A parsing filter and 10 detection rules |

## Before you begin

- A Collector must be installed and online. If you do not have one, see **UTMStack Forwarder**. One Collector can serve all your integrations.
- The FortiWeb must reach the Collector host on the port you choose. Open it on the Collector host and on any firewall in between.
- You need the `integrations.write` permission to enable the integration from the web interface.

## Step 1: Enable the integration on a Collector

<Steps>
  <Step title="Open the integration">
    In UTMStack, go to **Configure > Integrations** and open the **Fortiweb** card.
  </Step>
  <Step title="Choose the Collector, protocol and port">
    Under **Enable this integration remotely**, select the **Collector**, the **Protocol** (**UDP**, **TCP** or **TLS**) and the **Port**. The port fills in with the default for the protocol.
  </Step>
  <Step title="Enable it">
    Click **Enable integration**. The panel then shows, for example, `Currently: enabled · udp · port 7018`.
  </Step>
</Steps>

To do the same on the Collector host instead, run:

```bash
sudo /opt/utmstack-forwarder/utmstack_forwarder enable-integration firewall-fortiweb 7018 udp
```

To use TLS, load a certificate on the Collector first. See **UTMStack Forwarder**.

## Step 2: Configure FortiWeb to forward logs

On the FortiWeb, create a syslog policy pointing at the Collector host on port 7018 and turn on syslog logging. Run the following from the FortiWeb CLI, or use **Log & Report → Log Policy → Syslog Policy** in the web interface. Replace `<collector-ip>` with the address of the Collector host.

```text
config log syslog-policy
    edit "utmstack"
        config syslog-server-list
            edit 1
                set server <collector-ip>
                set port 7018
            next
        end
    next
end
config log syslogd
    set status enable
    set policy "utmstack"
end
```

<Note>

The setup guide in UTMStack fills in your UTMStack server's address in this step. Keep it only if the Collector runs on the UTMStack server; otherwise use the address of the Collector host.

</Note>

Make sure the log types you need (Attack, Event, Traffic) are enabled to be sent to syslog under the Log & Report settings.

## Step 3: Check that logs arrive

- In the **Fortiweb** drawer, click **View logs**. Log Explorer opens with the `firewall-fortiweb` data type for the last 24 hours.
- Within about 10 minutes, the FortiWeb appears on the **Data Sources** page under **Direct**.
- **Rules** and **Filters** in the same drawer open the detection rules and the parsing filter for this data type.

## Stop collecting

In the **Fortiweb** card, select the same Collector and click **Disable integration**, or run on the Collector host:

```bash
sudo /opt/utmstack-forwarder/utmstack_forwarder disable-integration firewall-fortiweb udp
```
