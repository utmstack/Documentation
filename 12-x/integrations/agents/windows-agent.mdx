The UTMStack Windows agent is a service you install on each Windows host. It reads the Windows Event Log and sends the events to UTMStack v12 over an encrypted connection on port 443. It also lets your team run response commands on the host.

## Before you begin

- The host must reach your UTMStack server on **443/TCP**. No other port is needed.
- You need a PowerShell window opened with **Run as administrator** on the host.
- You need the install command from your own UTMStack instance. It contains your connection key, which only administrators can see. See **How Data Reaches UTMStack**.
- Choose the build that matches the host's processor: **AMD64** (most PCs and servers) or **ARM64**.

<Tip>

You do not need to install cURL first. The command uses `curl.exe` when Windows has it, and the built-in .NET downloader when it does not.

</Tip>

## Install the agent

<Steps>
  <Step title="Open the Windows Agent card">
    In UTMStack, go to **Configure > Integrations** and open the **Windows Agent** card.
  </Step>
  <Step title="Choose the platform and options">
    Under **Install on Windows Agent**, choose the **Platform** (**AMD64** or **ARM64**) and set the **Options** (see the table below).
  </Step>
  <Step title="Copy the command">
    Copy the command shown. It contains a sensitive enrollment token: do not share it.
  </Step>
  <Step title="Run it on the host">
    Paste the command into the administrator PowerShell window and press Enter. Run it on every Windows host you want to monitor.
  </Step>
</Steps>

The command looks like this (the product fills in your server address and key):

```powershell
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12; [Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}; New-Item -ItemType Directory -Force -Path "C:\Program Files\UTMStack\UTMStack Agent" | Out-Null; if (Get-Command curl.exe -ErrorAction SilentlyContinue) { & curl.exe -k -o "C:\Program Files\UTMStack\UTMStack Agent\utmstack_agent_service_windows_amd64.exe" "https://<server>/private/dependencies/agent/utmstack_agent_service_windows_amd64.exe" } else { (New-Object Net.WebClient).DownloadFile('https://<server>/private/dependencies/agent/utmstack_agent_service_windows_amd64.exe', 'C:\Program Files\UTMStack\UTMStack Agent\utmstack_agent_service_windows_amd64.exe') }; Start-Process "C:\Program Files\UTMStack\UTMStack Agent\utmstack_agent_service_windows_amd64.exe" -ArgumentList 'install', '<server>', '<connection-key>', 'yes' -NoNewWindow -Wait
```

The command downloads the agent into `C:\Program Files\UTMStack\UTMStack Agent`, checks that the server answers on 443, registers the agent and starts it as a Windows service.

### Install options

| Option | Default | Effect |
|---|---|---|
| **Skip TLS certificate validation (self-signed server)** | On | The agent accepts the server's certificate without checking it. Leave it on if your UTMStack server uses its self-signed certificate. Turn it off if the server has a certificate your hosts trust. In the command this is the last argument, `'yes'` or `'no'`. |
| **Disable remote command execution on this host** | Off | Adds `'--no-remote-control'`. The agent then refuses every remote command, from the Data Sources console and from SOAR. This can only be undone by reinstalling the agent on the host. |

## What the agent collects

The agent reads these Windows Event Log channels and sends them under the data type `wineventlog`:

- Security, Application, System
- Windows PowerShell and Microsoft-Windows-PowerShell/Operational
- ForwardedEvents
- Microsoft-Windows-WinLogon/Operational
- Microsoft-Windows-Windows Firewall With Advanced Security/Firewall
- Microsoft-Windows-Windows Defender/Operational
- Microsoft-Windows-TaskScheduler/Operational
- Microsoft-Windows-TerminalServices-RDPClient/Operational, -LocalSessionManager/Operational and -RemoteConnectionManager/Operational
- Microsoft-Windows-WinRM/Operational
- Microsoft-Windows-NTLM/Operational
- Microsoft-Windows-CodeIntegrity/Operational
- Microsoft-Windows-WMI-Activity/Operational
- Microsoft-Windows-GroupPolicy/Operational
- Microsoft-Windows-SmbClient/Security
- Microsoft-Windows-PrintService/Operational
- Microsoft-Windows-Sysmon/Operational, when Sysmon is installed

## What the agent changes on the host

Windows leaves many useful audit events turned off by default. When it installs, the agent turns them on so the channels above contain the events the detection rules need:

- **Audit policy**: success and failure auditing for Process Creation, Process Termination, Logon, Logoff, Account Lockout, Special Logon, Other Logon/Logoff Events, Security Group Management, User Account Management, Audit Policy Change and Sensitive Privilege Use.
- **Command lines in process events**: sets `ProcessCreationIncludeCmdLine_Enabled` to 1 under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit`.
- **PowerShell logging**: turns on Script Block Logging and Module Logging (for all modules) under `HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell`.
- **Event channels**: enables the TaskScheduler/Operational and PrintService/Operational channels, which Windows ships disabled.

The agent only turns settings on. It never turns off or narrows an audit setting you already have.

<Note>

On domain-joined hosts, a Group Policy Object that manages the same audit settings can overwrite these values at its next refresh. Your Group Policy then decides what is audited.

</Note>

<Warning>

Uninstalling the agent does not turn these settings back off. If you need the previous audit policy, restore it yourself after you uninstall.

</Warning>

## After you install

- The host appears on the **Data Sources** page, under **Agents**, within about a minute of the agent starting.
- Its events appear in Log Explorer under the data type `wineventlog`. Use **View logs** in the Windows Agent drawer to open them.
- The **Agents** dashboard shows activity across all your agents.
- The agent keeps itself up to date. See **Updates and Status**.

To check the agent on the host, see **Agent Command Line**.

## Uninstall the agent

Open the **Windows Agent** card, choose the same **Platform**, and expand **Uninstall the agent** at the bottom of the guide. Run the command in an administrator PowerShell window. It:

1. runs the agent's own `uninstall` command, which also removes the updater service,
2. stops and deletes the agent services,
3. waits 10 seconds and deletes `C:\Program Files\UTMStack\UTMStack Agent`.
