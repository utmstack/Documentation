## Rule Example

Below is an example of a rule definition for **Abnormal Guest User Invitation Activity** ([view in repository](https://github.com/utmstack/UTMStack/blob/v12/definitions/rules/office365/guest_user_invitation_spikes.yaml)):

```yaml
# Rule version v1.0.0

dataTypes:
  - o365
name: Abnormal Guest User Invitation Activity
impact:
  confidentiality: 3
  integrity: 2
  availability: 1
category: Identity and Access Management
technique: Account Creation
adversary: origin
references:
  - https://learn.microsoft.com/en-us/purview/audit-log-activities
  - https://attack.mitre.org/techniques/T1136/
description: |
  Detects unusual spikes in guest user invitations which could indicate an attempt to establish persistence through external accounts or potential data exfiltration preparation by adding unauthorized external collaborators.
  
  Next Steps:
  1. Review the user account initiating the invitations for any signs of compromise
  2. Verify the legitimacy of the invited external users and their business justification
  3. Check if the inviting user has appropriate permissions for guest invitations
  4. Examine the invited users' email domains for suspicious or unexpected organizations
  5. Review any subsequent activity by the invited guest users
  6. Validate that the invitation frequency aligns with normal business processes
  7. Consider implementing additional approval workflows for guest user invitations
where: |
  equals("log.Workload", "AzureActiveDirectory") && 
  (
    equals("action", "Invite external user") ||
    equals("action", "InviteGuest") ||
    equals("action", "Add guest to group") ||
    equals("action", "Guest user invite redeemed")
  ) &&
  equals("actionResult", "success")
afterEvents:
  - with:
      - field: origin.user
        operator: filter_term
        value: '{{.origin.user}}'
      - field: action
        operator: filter_term
        value: 'Invite external user'
    within: 1h
    count: 10
groupBy:
  - adversary.user

```

### Microsoft 365 Double-Extension Executable Staged

Detects files on OneDrive for Business or SharePoint Online whose name contains a hidden ".exe." double extension (e.g., "invoice.exe.pdf", "report.exe.docx"). Attackers use double extensions to disguise malicious executables as documents so users and security tooling treat them as benign.

Verified against live Unified Audit data: file operations carry target.filename (full name) and log.SourceFileExtension (real last extension). The rule fires when the name embeds ".exe." but the true extension is not "exe".

Check the destination in the rule parameters, who made the change and recent sign-ins for the mailbox. Clearing a forwarding setting in an existing rule also raises this alert. The alert does not by itself establish compromise or an external recipient.

- **Category:** Collection
- **Technique:** T1114.003 - Email Collection: Email Forwarding Rule
- **Impact:** C:2 / I:1 / A:0
- **Rule file:** [mail_forwarding_rules.yaml](https://github.com/utmstack/UTMStack/blob/v12/definitions/rules/office365/mail_forwarding_rules.yaml)

### Suspicious Teams Message Export Activity

Detects when Teams messages are exported or read in bulk through Microsoft Graph API calls, which could indicate an attempt to exfiltrate chat history and shared files from Microsoft Teams. Microsoft logs MessagesListed only when an application retrieves messages through the Graph API, never for the Teams client, and backup or compliance tools do this continuously. The rule triggers when the identity behind an export or listing operation has 100 or more Teams records within one hour. One alert is raised per identity and application; repeats are suppressed for seven days.

- **Category:** Data Exfiltration
- **Technique:** T1114 - Email Collection
- **Impact:** C:3 / I:2 / A:1
- **Rule file:** [teams_data_exfiltration.yaml](https://github.com/utmstack/UTMStack/blob/v12/definitions/rules/office365/teams_data_exfiltration.yaml)
- **Reference:** [https://learn.microsoft.com/en-us/purview/audit-teams-audit-log-events](https://learn.microsoft.com/en-us/purview/audit-teams-audit-log-events)
- **Reference:** [https://learn.microsoft.com/en-us/purview/audit-log-activities](https://learn.microsoft.com/en-us/purview/audit-log-activities)

### Threat Intelligence Alert Pattern

### eDiscovery Abuse Detection

Detects potential abuse of eDiscovery features including excessive searches, exports, or unauthorized access to sensitive data through eDiscovery operations. This rule identifies users performing multiple eDiscovery actions within a short timeframe, which could indicate malicious data staging or exfiltration attempts.

- **Category:** Data Exfiltration
- **Technique:** T1074 - Data Staged
- **Impact:** C:3 / I:2 / A:1
