```yaml
adversary: origin
description: "Detects when a user has been added to the administrators group (sudo) on a Linux system."
references:
  - "https://attack.mitre.org/tactics/TA0004"
  - "https://attack.mitre.org/techniques/T1484/"
where: |
  regexMatch("origin.command", "(usermod.*-aG.*sudo|usermod.*-aG.*admin|gpasswd -a .* sudo|adduser .* sudo)")
deduplicateBy:
  - dataSource

```

### System Linux: BPF filter applied using TC

Detects when the tc (transmission control) binary is utilized to set a BPF (Berkeley Packet Filter) on a network interface. Tc is used to configure Traffic Control in the Linux kernel. It can shape, schedule, police and drop traffic. A threat actor can utilize tc to set a bpf filter on an interface for the purpose of manipulating the incoming traffic. This technique is not at all common and should indicate abnormal, suspicious or malicious activity.

- **Category:** Execution

### System Linux: Base64 or OpenSSL Decode Command Executed

Detects a standalone base64 -d/--decode or openssl enc -d invocation. Low-confidence alone (routinely used by legitimate scripts, cert handling, CI/CD), but a useful triage building block. Exists as a separate, lower-severity rule from 'Base64 or OpenSSL Decode Piped to a Shell' because the native auditd collector emits one execve event per process in a pipeline -- 'X | base64 -d | bash' never puts 'bash' inside base64's own origin.command; only a single-process 'sh -c "...|bash"' compound invocation does. Modeled on SigmaHQ's proc_creation_lnx_base64_decode.yml (level: low).

- **Category:** Defense Evasion

### System Linux: Base64 or OpenSSL Decode Piped to a Shell

Detects a base64 -d/--decode or openssl enc -d invocation whose command line also references a shell interpreter, consistent with decoding an obfuscated payload and executing it in one step -- a common one-liner pattern in droppers/loaders. Only fires for the single-process compound form (e.g. 'sh -c "...|base64 -d|bash"'), since the native auditd collector emits one execve event per process in a real shell pipeline and a piped 'base64 -d' alone never sees the downstream 'bash' in its own origin.command. See also 'Base64 or OpenSSL Decode Command Executed' (base64_openssl_decode_executed.yaml) for the standalone, lower-confidence variant that catches the common piped case.

- **Category:** Defense Evasion
- **Technique:** T1140 - Deobfuscate/Decode Files or Information
- **Impact:** C:1 / I:3 / A:1
- **Rule file:** [deobfuscate_decode_command.yaml](https://github.com/utmstack/UTMStack/blob/v12/definitions/rules/linux/deobfuscate_decode_command.yaml)
- **Reference:** [https://attack.mitre.org/techniques/T1140/](https://attack.mitre.org/techniques/T1140/)

### System Linux: File made Immutable by Chattr

Detects a file being made immutable using the chattr binary. Making a file immutable means it cannot be deleted or renamed, no link can be created to this file, most of the file is metadata can not be modified, and the file can not be opened in write mode. Threat actors will commonly utilize this to prevent tampering or modification of their malicious files or any system files they have modified for purposes of persistence

- **Category:** Defense Evasion
- **Technique:** T1222 - File and Directory Permissions Modification
- **Impact:** C:1 / I:2 / A:3
